# 분류 모델 가이드 (발표·보고서용)

> 이 문서는 **내가 만든 분석을 내 말로 설명할 수 있게** 돕기 위한 것입니다. 코드를 돌리는 것보다, 아래 내용을
> 이해하고 설명하는 것이 더 중요합니다.

## 1. 한 줄 요약

> 투구가 홈플레이트를 지날 때의 **위치와 구종**만 보고, 그 공이 **스트라이크인지 볼인지**를 맞히는 **이진 분류 모델**을
> 만들고, 여러 모델을 **처음 보는 데이터**로 평가해 비교했다.

## 2. 왜 이것이 '분류'인가

| 질문 | 답 |
|---|---|
| 맞히려는 값이 숫자의 크기인가, 종류인가? | **종류**(스트라이크 / 볼) → 분류. (숫자를 맞히면 회귀) |
| 학습할 때 정답이 붙어 있는가? | **있다**(`is_strike`) → 지도학습. (정답 없이 묶으면 군집) |
| 범주가 몇 개인가? | **2개** → 이진 분류 |

참고: 앞서 만든 "장타형/단타형"은 ISO ≥ 0.160이라는 기준을 **사람이 정해서** 나눈 것이라 분류 모델이 아닙니다. 이 프로젝트의
분류 모델은 **스트라이크/볼**입니다.

## 3. 데이터: 정답(라벨)과 입력(특징)

| 구분 | 컬럼 | 설명 |
|---|---|---|
| **정답(라벨)** | `is_strike` | 스트라이크 판정이면 1, 볼이면 0 (루킹·헛스윙·파울 포함) |
| 특징 | `plate_x`, `plate_z` | 공이 홈플레이트를 지날 때 좌우·높이(ft) |
| 특징 | `is_fast` | 직구면 1, 변화구면 0 |
| 파생 특징 | `abs_x`, `z_dist`, `zone_dist` | 존 중심에서 떨어진 거리 (직접 계산해서 추가한 변수) |

## 4. 비교한 모델 5개

| 모델 | 하는 일 | 왜 넣었나 |
|---|---|---|
| 기준선 | 학습 없이 **항상 더 많은 쪽**만 찍음 | 이보다 못하면 학습이 의미 없다는 **최소 기준** |
| 로지스틱 회귀(원본 좌표) | 직선 하나로 두 범주를 나눔 | 가장 단순한 모델. 사각형 존은 직선으로 못 나눠서 약할 것으로 예상 |
| 로지스틱 회귀(파생변수) | 위 모델 + 거리 변수 | **변수를 잘 만들면 단순한 모델도 좋아진다**는 것을 보이려고 |
| 결정트리 | "x가 0.8보다 작은가?" 같은 질문을 이어서 나눔 | 사각형 존을 자연스럽게 학습, 사람이 읽기 쉬움 |
| 랜덤포레스트 | 결정트리 여러 그루의 다수결 | 보통 안정적이고 성능이 좋음 |

## 5. 평가 방법 (가장 중요)

1. **학습/테스트 분리**: 데이터의 80%로 학습하고, 학습에 쓰지 않은 20%로만 성능을 잰다.
   (외운 문제로 시험 보면 점수가 부풀려지기 때문)
2. **층화 추출**: 스트라이크/볼 비율이 학습과 테스트에서 같게 나눈다.
3. **교차검증(CV)**: 학습 데이터를 5번 다르게 나눠 정확도의 평균과 흔들림(표준편차)을 본다.
4. **난수 시드 고정**: 같은 시드면 항상 같은 결과가 나온다(재현 가능).

### 지표를 쉽게 읽기
| 지표 | 뜻 | 예 |
|---|---|---|
| 정확도 | 전체 중 맞힌 비율 | 100구 중 82구 맞힘 → 0.82 |
| 정밀도 | "스트라이크"라고 한 것 중 진짜 스트라이크 비율 | 높으면 헛다리가 적음 |
| 재현율 | 진짜 스트라이크 중 모델이 찾아낸 비율 | 높으면 놓친 게 적음 |
| F1 | 정밀도와 재현율의 균형 | 둘 다 높아야 높음 |
| ROC-AUC | 스트라이크와 볼을 얼마나 잘 구분하나 (0.5 = 무작위, 1.0 = 완벽) | 0.81이면 꽤 잘 구분 |
| 혼동행렬 | 맞힌 것과 틀린 것을 네 칸으로 정리 | 볼→스트라이크로 잘못 예측한 수 등 |

> ⚠ **정확도만 보면 속습니다.** 스트라이크가 64%인 데이터에서 "무조건 스트라이크"라고만 해도 정확도가 0.64입니다.
> 그래서 **기준선**과 비교하고, ROC-AUC와 혼동행렬을 같이 봐야 합니다.

## 6. 그림 읽는 법

- **스트라이크 확률 지도**(`probability_map.png`): 위치마다 모델이 예측한 스트라이크 확률. 진할수록 스트라이크 가능성이 높고,
  빨간 점선은 확률 50% 경계(모델이 그은 "스트라이크존")다. 직구와 변화구 지도를 비교할 수 있다.
- **평가 그림**(`evaluation.png`): ① 혼동행렬 ② ROC 곡선(왼쪽 위로 휠수록 좋음) ③ 모델별 F1.

## 7. 예상 질문과 답 (선생님이 물어볼 만한 것)

**Q1. 왜 분류인가요?**
맞히려는 값이 스트라이크/볼이라는 범주이고, 정답이 붙은 데이터로 학습했기 때문입니다(지도학습의 이진 분류).

**Q2. 왜 학습 데이터와 테스트 데이터를 나눴나요?**
모델이 학습 데이터를 외웠는지가 아니라 처음 보는 공도 맞히는지를 확인하려고 나눴습니다.

**Q3. 정확도가 높은데 왜 기준선과 비교하나요?**
범주 비율이 한쪽으로 치우치면 아무것도 안 배워도 정확도가 높게 나오기 때문에, 기준선보다 얼마나 나은지가 진짜 성능입니다.

**Q4. 로지스틱 회귀가 처음엔 못했는데 왜 좋아졌나요?**
스트라이크존은 사각형에 가까워서 직선 하나로는 나눌 수 없습니다. 존 중심에서의 거리 변수를 더하니 선형 모델도 구분할 수 있게 됐습니다.

**Q5. 정확도가 100%가 안 나오는 이유는요?**
`is_strike`에는 타자가 휘두른 공(헛스윙, 파울)이 포함되어 있고, 심판 판정이나 타자 키에 따라 존이 달라지는데 이런 정보는 쓰지 않았습니다.

**Q6. 과적합이 아닌지 어떻게 알았나요?**
테스트 데이터 성능과 교차검증 성능이 비슷하고, 교차검증 표준편차가 작으면 한 번의 운이 아니라는 근거가 됩니다.

**Q7. 어떻게 개선할 수 있나요?**
볼카운트, 타자의 좌/우 타석, 타자 키(존 크기), 투수 변수를 추가하거나 데이터 양을 늘릴 수 있습니다.

## 8. 실제 데이터 사용하기 (제출용)

`--demo`는 프로그램이 **무작위로 만든 가짜 데이터**라서, 그 수치를 실제 분석 결과처럼 제출하면 안 됩니다. 제출용 분석에는 실제
투구 위치 데이터가 필요합니다.

KBO는 투구 위치를 내려받을 수 있게 공개하지 않으므로, **MLB Statcast**(실제 공개 데이터)를 쓰는 방법이 있습니다.
이 경우 보고서에 "KBO가 아니라 MLB Statcast 데이터를 사용했다"고 **정확히** 적고, 선생님께 주제 범위가 괜찮은지 미리 확인하세요.

```bash
# 방법 A (가장 확실): Baseball Savant의 Statcast Search에서 기간·조건을 정하고 CSV를 내려받은 뒤 변환
python -m kbo_heatmap.statcast --from-csv savant.csv --out data/pitches_statcast.csv

# 방법 B: pybaseball로 기간을 지정해서 내려받기 (pip install pybaseball 필요)
python -m kbo_heatmap.statcast --start 2026-06-01 --end 2026-06-07 --out data/pitches_statcast.csv

# 분류 실행
python -m kbo_heatmap.classify_cli --data data/pitches_statcast.csv
```

변환 규칙: 볼(B)=0, 스트라이크(S: 루킹·헛스윙·파울)=1, 인플레이(X)는 제외.
